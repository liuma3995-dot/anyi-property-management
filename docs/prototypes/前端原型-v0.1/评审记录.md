## 五、已知偏差与遗留

1. 字体偏差见 §二（原型字体 ≠ 微软雅黑，开发时回退）；
2. 原型源文件为 `quanju.pen`（pen.dev 格式），如需 .epgz 需另行导出转换；
3. 弹窗类交互（确认框、表单弹层）以文字标注 + 页内表单区示意，未单独出弹窗页；如评审要求可补弹窗细节页；
4. 移动端 / 自助端（业主扫码缴费等）不在本期范围，设备页预留二维码说明。

## 九、r3 修复明细（2026-08-28 第二轮评审意见）

**#4a 表格列错位（12 页 26 行）**：根因为行数据比表头多一个单元格——当一行含两个操作（如"发布+编辑"）时被拆成两个单元格，多余单元格按 fill_container 布局挤占"收费项目"等弹性列，整行左移错位。涉及：PG-INF-05、PG-FIN-02、PG-FIN-05、PG-FIN-06、PG-EMG-03、PG-EMG-04（额外发现）、PG-ORG-01、PG-TEL-02（额外发现）、PG-DIS-03、PG-EQP-01、PG-EQP-04、PG-COM-01。修复：多余单元格的动作文本合并进操作列（保留各自颜色），删除冗余单元格；PG-DIS-03 调解表两行为误写的行尾数字，直接删除。

**#4b 表格列溢出（PG-EMG-04）**："关联事件"列固定宽 116px 不足容纳"EM-2608-11 水浸"等内容且与相邻列重叠。修复：重排列宽（88/168/112/112/48/40/56），并修复该页右卡未生效的宽度设定（见 #4c），表格恢复 7 列完整显示。

**#4c 双栏卡片宽度未生效（6 页）**：卡片宽度在脚本中以 JS 变量赋值方式设置（如 `right.width=420`），未作用到节点，卡片实际为 fill_container（左右各半 543px），进而压缩表格宽度。涉及：PG-EMG-01（场景库 300）、PG-FIN-03（收款表单 430）、PG-DIS-03（时间线 280 / 结案 330）、PG-EMG-04（详情 420）、PG-EQP-02（设备卡 380）、PG-FIN-07（报表参数 300）。修复：全部改为节点 Update 生效。

**#5 "复"字显示大小不正常**：现象为"复盘"等词中"复"字形明显大于同串其他字（见 PG-EMG-04 侧栏导航项、提醒条、详情标题等）。已通过消除合成加粗（当前页子项改常规字重，高亮由底色承担）并强制显式字体后恢复正常；同步全量重导出后各页"复"字渲染一致。
