# DM-6 交互时序设计

> 制品：DM-06 ｜ 版本：v0.2（前后端分离，经 HTTP API 交互）｜ 状态：待评审
> 输入：AM-04 关键流程、AM-02 关键用例、技术选型建议
> 说明：8 个关键用例时序图；前端（WPF）与后端（本地 API 服务）之间经 `127.0.0.1:5210/api/v1` HTTP/JSON 交互；参与者为系统管理员（唯一角色）。

## 一、登录

```mermaid
sequenceDiagram
  participant A as 管理员
  participant UI as 前端界面
  participant API as 后端 API
  participant AU as 认证服务
  participant DB as 数据库
  A->>UI: 输入账号密码
  UI->>API: POST /auth/login
  API->>AU: 校验账号与密码
  AU->>DB: 查询账号
  alt 校验成功
    DB-->>AU: 账号有效
    AU-->>API: 签发 token
    API-->>UI: 返回 token + 模块清单
    UI-->>A: 进入仪表盘
  else 连续失败 5 次
    AU-->>API: 锁定 30 分钟
    API-->>UI: 提示锁定
  end
```

## 二、生成账单（草稿→发布）

```mermaid
sequenceDiagram
  participant A as 管理员
  participant UI as 前端界面
  participant API as 后端 API
  participant BS as 账单服务
  participant DB as 数据库
  A->>UI: 选择收费项目/周期/范围
  UI->>API: POST /bills/generate
  API->>BS: 生成账单请求
  BS->>DB: 检查同周期重复（BR-FIN-01）
  alt 无重复
    BS->>DB: 生成账单（待发布）
    BS-->>API: 草稿清单 + 失败清单
    API-->>UI: 返回草稿
    A->>UI: 核对并发布
    UI->>API: POST /bills/publish
    API->>BS: 发布
    BS->>DB: 状态更新为待缴
    BS-->>API: 发布完成
    API-->>UI: 发布完成
  else 已存在同周期账单
    BS-->>API: 阻止并提示
    API-->>UI: 阻止并提示
  end
```

## 三、收款（部分缴/预存）→ 收据

```mermaid
sequenceDiagram
  participant A as 管理员
  participant UI as 前端界面
  participant API as 后端 API
  participant PS as 收款服务
  participant DB as 数据库
  participant PR as 打印机
  A->>UI: 选择业主/房产与待缴账单
  A->>UI: 录入收款金额/方式
  UI->>API: POST /payments
  API->>PS: 提交收款
  PS->>DB: 事务开始
  alt 金额 < 账单金额
    PS->>DB: 账单转"部分缴"，剩余计欠费
  else 金额 = 账单金额
    PS->>DB: 账单转"已缴"
  else 金额 > 账单金额
    PS->>DB: 多缴转预存款（P-06）
  end
  PS->>DB: 生成缴费记录 + 收据 + 审计
  PS->>DB: 事务提交
  PS-->>API: 收款结果 + 收据号
  API-->>UI: 返回收据数据
  UI-->>A: 收款成功
  A->>PR: 前端打印收据
```

## 四、登记支出

```mermaid
sequenceDiagram
  participant A as 管理员
  participant UI as 前端界面
  participant API as 后端 API
  participant ES as 支出服务
  participant DB as 数据库
  A->>UI: 选择支出分类/金额/说明
  UI->>API: POST /expenses
  API->>ES: 提交支出
  ES->>DB: 校验分类（BR-FIN-04）
  ES->>DB: 保存支出 + 关联对象（员工/设备/维保）

  ES-->>API: 保存成功
  API-->>UI: 完成
```

## 五、应急响应全流程

```mermaid
sequenceDiagram
  participant A as 管理员
  participant UI as 前端界面
  participant API as 后端 API
  participant ES as 应急服务
  participant DB as 数据库
  A->>UI: 选择场景/录入信息
  UI->>API: POST /emergency/events
  API->>ES: 发起事件
  ES->>DB: 关联场景，带出步骤（当前版本）
  ES->>DB: 匹配责任人/值班人
  alt 有匹配
    ES->>DB: 写入指派
  else 无匹配
    API-->>UI: 提示人工指派或暂不指派
    A->>UI: 人工指派（或确认暂不指派）
    UI->>API: PUT /emergency/events/{id}/assign
    ES->>DB: 发起人默认为第一处置人
  end
  A->>UI: 记录处置过程（可多次）
  UI->>API: POST /emergency/records
  A->>UI: 结案
  UI->>API: POST /emergency/events/{id}/close
  A->>UI: 复盘（3 个工作日内）
  UI->>API: POST /emergency/reviews
  API-->>UI: 事件转"已复盘"
```

## 六、纠纷登记→处理→结案

```mermaid
sequenceDiagram
  participant A as 管理员
  participant UI as 前端界面
  participant API as 后端 API
  participant DS as 纠纷服务
  participant DB as 数据库
  A->>UI: 登记纠纷（类型/当事人/详情）
  UI->>API: POST /disputes/cases
  API->>DS: 保存案件（已登记→处理中）
  A->>UI: 记录处理方案（可追加）
  UI->>API: POST /disputes/records
  A->>UI: 结案（选择结案类型）
  UI->>API: POST /disputes/cases/{id}/close
  DS->>DB: 校验存在处理记录（BR-DIS-02）
  DS->>DB: 案件转"已结案"并归档
  API-->>UI: 结案成功
```

## 七、设备到期提醒→保养登记

```mermaid
sequenceDiagram
  participant SYS as 后端服务
  participant DB as 数据库
  participant UI as 前端界面
  participant A as 管理员
  participant API as 后端 API
  SYS->>DB: 按周期计算到期设备（P-04）
  SYS-->>UI: GET /reminders 返回待办
  UI-->>A: 仪表盘/待办展示
  A->>UI: 点击提醒，进入设备档案
  A->>UI: 登记保养（日期/内容/结果/单位）
  UI->>API: POST /equipment/maintenance
  API->>DB: 保存保养记录
  alt 结果合格
    DB->>DB: 计算下次保养日期
  else 结果不合格
    API->>DB: 设备转"维修中"，可关联故障
  end
  API-->>UI: 提醒销项
```

## 八、基础数据 Excel 导入

```mermaid
sequenceDiagram
  participant A as 管理员
  participant UI as 前端界面
  participant API as 后端 API
  participant IS as 导入服务
  participant DB as 数据库
  A->>UI: 下载模板并填写
  A->>UI: 上传 Excel（multipart）
  UI->>API: POST /baseinfo/import
  API->>IS: 逐行校验（BR-INF-05）
  alt 全部通过
    IS->>DB: 批量入库并生成关系
    IS-->>API: 导入成功
    API-->>UI: 成功提示
  else 部分错误
    IS->>DB: 正确行入库
    IS-->>API: 错误清单
    API-->>UI: 返回错误清单（可下载）
    A->>UI: 修正后重导错误行
  end
```

## 九、追溯说明

- 本制品与 AM-04 流程一一对应：登录/基础信息/账单/收款/支出/应急/纠纷/设备；
- 前端与后端之间仅传输 DTO（JSON），事务边界全部在后端（时序中的"事务开始/提交"）；
- 打印由前端调用本地打印机；导入/导出/备份文件由后端生成，前端负责上传、下载与打开。
