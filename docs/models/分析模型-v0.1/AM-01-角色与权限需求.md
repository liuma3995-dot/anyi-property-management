# AM-1 角色与权限需求

> 制品：AM-01 ｜ 版本：v0.4（按评审结论调整：仅保留系统管理员角色）｜ 状态：待评审

## 一、评审结论（角色简化）

经评审确认：本系统为小镇物业管理使用，人员配置少，**系统登录角色仅设一个"系统管理员"**，不再区分财务、前台、安保、工程等系统角色。

- 员工、部门、岗位仍作为**业务数据**在人员组织子系统中维护（排班、考勤、工资、应急值班等业务照常记录）；
- 业务上的分工（谁收费、谁处置、谁值班）由现场安排，**系统不区分操作人身份**；
- 登录账号与业务员工档案解耦：管理员账号只用于系统登录与操作，不等于某一名员工档案。

## 二、角色清单

| 角色编号 | 角色 | 职责 |
|---|---|---|
| R01 | 系统管理员 | 唯一角色。拥有全部模块访问权限，负责日常业务操作（收费、应急、纠纷、设备、电话簿等）、基础数据维护、账号与参数管理、数据备份恢复 |

## 三、模块访问

系统管理员拥有七大子系统 + 公共支撑能力的全部操作权限（查看/新增/修改/删除/导出/打印），按模块导航直接使用：

| 模块 | 访问权限 |
|---|---|
| 基础信息（业主/房产/车位） | 全部操作 |
| 财务收费 | 全部操作 |
| 应急处置 | 全部操作 |
| 人员组织 | 全部操作 |
| 便民电话簿 | 全部操作 |
| 民事纠纷调解 | 全部操作 |
| 设备资产台账 | 全部操作 |
| 公共（账号/审计/备份/字典） | 全部操作 |

## 四、权限与安全原则（简化后）

1. 系统仅一个管理员角色，登录账号可自行修改密码；不按员工个人配置权限；
2. 涉及金额的操作（收款、退款、调整、支出）与删除、结案、报废等敏感操作一律审计留痕，删除采用软删除；
3. 登录失败锁定与账号停用控制保留（BR-COM-02/03）；
4. 数据本地定期备份，支持恢复；
5. 后续如增加人员配置，再引入"岗位-角色-权限"模型，本期不设计（预留扩展点，不进入 AM-03 概念）。
