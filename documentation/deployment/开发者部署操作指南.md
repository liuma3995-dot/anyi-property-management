# 开发者部署操作指南

> 适用版本：安怡物业管理系统 1.3.0

本指南面向"拿到源码要把系统跑起来、并打出安装包"的开发者，从环境准备一路写到打包发布与故障排查。所有命令均已在 **Windows 10（64 位）**实测可用；**Win7 SP1 是立项要求的兼容平台，但尚未在真机验证**。

## 一、环境依赖

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | **Windows 7 SP1 及以上**（64 位为主） | 兼容 Win7 SP1 为立项要求：依赖统一选 net45/net46/netstandard2.0 兼容资产；Win10（64 位）已端到端验证，Win7 / Win11 未在真机验证 |
| 构建工具 | Visual Studio 2019 或 2022，含 **.NET Framework 4.8 目标包** 与 MSBuild | 仅需"使用 .NET 的桌面开发"工作负载 |
| 运行时 | .NET Framework 4.8 | Win10 1903+ / Win11 通常已内置；Win7 SP1 需安装（安装包已内嵌离线安装器）。可用注册表 `Release` 值确认（`≥ 528040` 表示已装） |
| 包管理 | NuGet CLI（`nuget.exe`） | 或在 Visual Studio 中使用包管理器还原 |
| 安装包工具 | **Inno Setup 6**（仅打包需要） | 提供 `ISCC.exe` 命令行编译器 |
| 磁盘 | 源码与产物约 2 GB（含 `packages/` 与 `bin/obj`） | 安装包产物另需约 130 MB |

> 如果本机曾安装过旧版本程序做联调，建议先停掉 `PropertyManagement.Server.exe` 与 `PropertyManagement.Client.exe`，避免产物文件被占用。

## 二、获取与还原

```powershell
git clone https://github.com/liuma3995-dot/anyi-property-management.git
cd anyi-property-management

# 还原 NuGet 依赖（首次或 packages.config 变更后）
nuget restore PropertyManagement.sln
```

常见还原问题：

- **离线环境**：可预先在可联网机器执行 `nuget restore`，再把整个 `packages/` 目录复制过来；本仓库不含 `packages/`。
- **源不可达**：检查 `NuGet.Config` 中的源配置与公司代理设置。
- **引用程序集缺失**：`.NET Framework 4.8` 目标包未安装时会报找不到 `System.*` 引用程序集，请回到第一步补装工作负载。

## 三、编译

```powershell
# 推荐：使用 Visual Studio 自带 MSBuild（版本随安装路径变化）
& "C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" `
    PropertyManagement.sln /p:Configuration=Debug /m /v:m /nologo

# 发布用 Release 产物（打包的唯一载体）
& "C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" `
    PropertyManagement.sln /p:Configuration=Release /m /v:m /nologo
```

产物位置与数量基线：

| 工程 | 输出 | 说明 |
|---|---|---|
| `PropertyManagement.Contract` | `bin\<配置>\PropertyManagement.Contract.dll` | 契约程序集，被客户端与后端共同引用 |
| `PropertyManagement.Server` | `bin\<配置>\PropertyManagement.Server.exe` | 约 71 个文件（含 SQLite 原生库 `x86/x64`、NLog.config） |
| `PropertyManagement.Client` | `bin\<配置>\PropertyManagement.Client.exe` | 约 25 个文件（含 HandyControl 等界面依赖） |
| `PropertyManagement.Tests` | `bin\<配置>\PropertyManagement.Tests.dll` | 单元测试程序集 |

常见编译问题：

- **目标包缺失**：报 `MSB3644` 找不到引用程序集 → 补装 .NET Framework 4.8 目标包。
- **平台不匹配**：SQLite 原生库分 `x86/x64` 两个子目录，请在 64 位进程下运行后端。
- **产物被占用**：`MSB3021` 无法复制文件 → 停掉正在运行的服务端/客户端再编译。

## 四、运行与调试

系统为单机前后端分离形态，**必须先启动后端，再启动客户端**：

```powershell
# 终端 1：本地后端（监听 http://127.0.0.1:5210）
.\PropertyManagement.Server\bin\Debug\PropertyManagement.Server.exe

# 终端 2：客户端
.\PropertyManagement.Client\bin\Debug\PropertyManagement.Client.exe

# 健康检查
Invoke-WebRequest http://127.0.0.1:5210/api/v1/health
```

| 机制 | 说明 |
|---|---|
| 监听地址 | 由 `PropertyManagement.Server\App.config` 的 `BaseAddress` 决定，默认 `http://127.0.0.1:5210`，**仅绑定回环地址，不暴露局域网** |
| 单实例互斥 | 服务端按监听端点加互斥体（`Global\...SingleInstance.<host_port>`，无权限时回退本地会话）；同一端口重复启动会**静默退出**，不抢端口；不同端口可并存 |
| 无控制台运行 | 无交互控制台时服务端不再依赖 `Console.ReadKey` 阻塞，改由进程等待，因此可以作为隐藏后台进程常驻 |
| 客户端启动编排 | 客户端启动时以 `GET /health` 为唯一判据探测后端：未就绪时按需拉起一次（同目录 `Server\`），并在约 20 秒等待窗口内轮询，登录页实时显示状态与重试次数 |
| `Api.Mode` | `Http`（默认，强制真实后端，不做降级）／ `Auto`（探测失败降级演示数据）／ `Mock`（强制演示数据）；生产与调试请保持 `Http`，避免掩盖"服务未就绪" |

调试建议：后端异常会写入 `%ProgramData%\PropertyManagement\logs\server-<日期>.log`；客户端崩溃日志写入 `%LOCALAPPDATA%\PropertyManagement\crash-<日期>.log`。

## 五、数据库与数据目录

```powershell
# 数据目录（默认；可用 App.config 的 DbDirectory 覆盖）
C:\ProgramData\PropertyManagement\
├─ data\        # property.db（SQLite 业务库）与附件
├─ logs\        # 服务端运行日志
├─ backups\     # 备份数据文件
├─ exports\     # 导出的报表与清单
└─ config\      # token.key 等运行期配置
```

| 项 | 说明 |
|---|---|
| 首次建库 | 首次启动自动执行 schema 与增量迁移，当前 **schema 版本 44**；旧库按版本逐级迁移，幂等可重跑 |
| `DbDirectory` | 留空使用 `%ProgramData%\PropertyManagement`；联调时可指向临时目录，避免污染本机数据 |
| `DevSeedEnabled` | 演示造数开关（源码默认 `false`）。置 `true` 时会在**空库**首次建库后写入演示数据（房产、业主、账单、设备、员工、应急场景等）用于界面联调；**正式环境必须保持 `false`** |
| 数据安全 | 严禁把库文件放在安装目录（Program Files 不可写）；删除一律软删，保留 `del_flag` 痕迹 |

## 六、测试

```powershell
# 单元测试：xUnit + 控制台 runner，共 181 例
powershell -NoProfile -ExecutionPolicy Bypass -File PropertyManagement.Tests\run-tests.ps1
```

要点：

- 测试使用 `%TEMP%\pm-tests\{时间戳}-{PID}\` 下的**隔离库**，不读写 `C:\ProgramData\PropertyManagement`；
- 覆盖后端领域规则（账单生成、收款与退款、状态流转、权限与审计等），每条规则含正向与反向用例；
- 输出包含断言总数与失败清单，退出码非 0 表示存在失败；
- 仓库另配 GitHub Actions（`.github/workflows/build.yml`）：Windows 上还原 → Release 编译 → 单元测试。

## 七、打包与发布

安装包由 **Inno Setup 6** 编译，脚本入口 `Installer\build-setup.ps1`。

**1) 准备运行时离线安装器**

脚本会把 `.NET Framework 4.8` 离线安装器内嵌进安装包，需先下载到指定位置（约 116 MB，**不纳入版本控制**）：

```powershell
# 官方地址（下载后核对签名与 SHA256）
Invoke-WebRequest 'https://go.microsoft.com/fwlink/?linkid=2088631' `
  -OutFile 'Installer\redist\ndp48-x86-x64-allos-enu.exe'
```

预期校验值（可用于比对）：文件大小 **121 346 568 B**，产品版本 **4.8.04115.00**，SHA256 **`0A3A390C47E639D0F7FC65B21195FEE6B7F65B066F80F70C60FAB191D14B7E40`**。

**2) 执行打包**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Installer\build-setup.ps1
```

脚本按以下顺序工作：解析 `ISCC.exe`（四级查找：`ISCC_PATH` 环境变量 → 注册表 `InstallLocation` → 常见安装路径 → `PATH`）→ 编译 Release 产物 → 生成向导品牌图 → 编译安装包 → 校验打包完整性 → 输出 SHA256、文件清单与构建记录到 `output\`。

| 参数 | 用途 |
|---|---|
| `-Version 1.1.1` | 注入版本串（影响包名、`Add/Remove Programs` 显示与安装包属性）；**默认取 `Build\Version.props` 的值**，显式传值与版本真值不一致时会直接失败 |
| `-AllowVersionOverride` | 显式允许 `-Version` 覆盖版本真值（仅在临时验证场景使用，正常发版请改 `Build\Version.props`） |
| `-SkipBuild` | 跳过 MSBuild 复用现有产物（会触发**产物新鲜度闸门**校验） |
| `-Rehearsal` | 生成"彩排版"安装包：非提权安装到 `tmp\` 目录、不写自启项、不建桌面快捷方式，用于在普通用户下验证打包树可运行 |

> **产物新鲜度闸门**：脚本会按项目比对「最新源码时间」与「产物构建时间」，若源码更新而产物未重编，会直接失败并提示去掉 `-SkipBuild`——避免把旧代码打进安装包。
>
> **版本元数据闸门（v1.1.1 起）**：脚本会校验编译产物的 `文件版本 / 产品版本 / 产品名称` 与本次打包版本完全一致，不一致直接失败——避免出现「安装包是 1.1.1、里面装的却是别的版本」或「产物没有版本信息」的情况。

**3) 产物与校验**

| 产物 | 说明 |
|---|---|
| `output\安怡物业管理系统-Setup-<版本>.exe` | 安装包（内含客户端、后端与 .NET 4.8 离线安装器） |
| `output\...-文件清单.txt` | 打包文件清单（Inno Setup 生成） |
| `output\...-构建记录.txt` | 版本、时间、ISCC 路径、SHA256、打包条目数等 |

交付前建议自行安装一次：安装目录 `C:\Program Files\PropertyManagement`（`Client\` 与 `Server\` 并列）、数据目录 `C:\ProgramData\PropertyManagement`，卸载默认保留数据。

**4) 版本口径与改版流程（v1.1.1 起）**

产品版本**只有一个手写来源**：`Build\Version.props`。

| 项 | 值 | 来源 |
|---|---|---|
| 展示版本（界面文案 / 健康检查 / 安装包文件名 / 产品版本） | `1.1.1` | `Version.props` 的 `AnyiVersion` |
| 程序集版本（`AssemblyVersion` / `AssemblyFileVersion`） | `1.1.1.0` | `AnyiVersion` + `.0` |
| 文件说明（FileDescription） | `安怡物业管理系统 客户端` 等 | `ProductInfo.targets` 按程序集名映射 |

实现方式：三个工程各一行 `<Import Project="..\Build\ProductInfo.targets" />`，由该目标在编译前生成
`obj\<配置>\ProductInfo.g.cs`（生成物不纳入版本控制）；运行期统一经 `Build\AppVersionInfo.cs` 读取
（客户端登录页与主界面、后端健康检查同源）。

**改版本只需两步**：

```powershell
# 1) 改 Build\Version.props 的 <AnyiVersion>（唯一改动点）
# 2) 打包（版本自动带入编译与安装包）
powershell -NoProfile -ExecutionPolicy Bypass -File Installer\build-setup.ps1
```

自检脚本（可选）：`tmp\v111\verify-version-info.ps1` 会断言 Debug/Release 产物的
文件版本、产品版本、产品名称、公司、说明是否齐全且与版本真值一致。

## 八、常见故障排查

| 现象 | 排查顺序 |
|---|---|
| 后端启动失败，端口占用 | `netstat -ano` 按端口 5210 过滤结束占用进程；或改 `BaseAddress` 换端口 |
| 后端启动报 AccessDenied（错误码 5） | 非管理员账号缺少 URL 保留权限：以管理员执行 `netsh http add urlacl url=http://127.0.0.1:5210/ user=%USERDOMAIN%\%USERNAME%` 后重试 |
| SQLite 原生库加载失败 | 确认 `x86\`/`x64\SQLite.Interop.dll` 已随程序一起复制；确认进程位数与库位数一致 |
| 客户端一直提示「本地服务未就绪」 | 按上文启动后端并访问 `/health`；确认 `Api.Mode=Http`；查看 `logs` 当日日志；确认 5210 未被防火墙或代理拦截 |
| 打包时提示找不到 `ISCC.exe` | 安装 Inno Setup 6，或设置环境变量 `ISCC_PATH` 指向 `ISCC.exe` |
| 打包时提示产物过期 | 去掉 `-SkipBuild` 重新编译 Release（闸门用于防止把旧代码打进包） |
| 导入模板/导出 Excel 报 `FileLoadException` | 确认 `DocumentFormat.OpenXml` 的程序集绑定重定向存在于 `App.config`（仓库已配置） |
| 修改 `App.config` 不生效 | `bin\` 下的 `.exe.config` 是编译产物副本，请改源码的 `App.config` 后重新编译 |
